    Le rendu optimiste¶

    Le problème à résoudre¶

    Sur un écran TFT sans mémoire tampon double (double buffer), chaque pixel dessiné est immédiatement visible. Effacer tout l'écran (le remplir de noir) avant de tout redessiner provoque un scintillement visible à chaque frame — un flash noir entre chaque image.

    De plus, effacer 240 × 135 = 32 400 pixels à chaque cycle est lent et inutile : dans la plupart des jeux, 95 % de l'écran n'a pas changé d'une frame à l'autre.

    La solution : rendu différentiel¶

    On ne touche que ce qui a changé. Pour un objet mobile, la séquence est systématiquement :

    1. Sauvegarder l'ancienne position  ←  avant de calculer la nouvelle
2. Calculer la nouvelle position
3. Effacer l'ancienne position      ←  peindre en noir à l'ancien endroit
4. Dessiner à la nouvelle position  ←  peindre en couleur au nouvel endroit

    ❌ Rendu naïf                      ✅ Rendu différentiel
─────────────────                  ──────────────────────────────
Effacer TOUT l'écran (noir)        Sauvegarder ancienne_x, ancienne_y
Redessiner TOUS les éléments       Calculer nouvelle position
                                   dessiner_rect(ancienne_x, ancienne_y, NOIR)
Résultat : flash noir visible      dessiner_rect(nouvelle_x, nouvelle_y, COULEUR)
           lent, coûteux
                                   Résultat : fluide, rapide, invisible

    Analogie : corriger une faute dans un texte manuscrit. La méthode naïve : réécrire la page entière. La méthode intelligente : passer la gomme sur le seul mot fautif, réécrire ce mot. Le résultat est identique, le travail est 100× moindre.

    Algorithme — Rendu différentiel pour un objet mobile¶

     Dans mettreÀJour() : sauvegarder avant de modifier
ancienne_x ← position_x
ancienne_y ← position_y

position_x ← position_x + vitesse_x
position_y ← position_y + vitesse_y

 Dans afficher() : effacer l'ancien, dessiner le nouveau
dessiner_rect(ancienne_x, ancienne_y, taille, taille, NOIR)    ← action de la gomme
dessiner_rect(position_x, position_y, taille, taille, COULEUR) ← action du crayon

    Les variables ancienne_x et ancienne_y font le lien entre mettreÀJour() et afficher(). C'est pourquoi elles sont sauvegardées dans la phase de mise à jour, pas dans la phase de rendu.

    Le premier dessin : cas particulier¶

    Le rendu différentiel suppose qu'un état de référence existe déjà à l'écran. Au tout premier frame, cet état n'existe pas encore. Il faut donc un dessin initial complet :

    si premier_dessin :
  premier_dessin ← FAUX
  effacer_écran()              ← l'unique fois où on efface tout
  dessiner_fond()
  dessiner_tous_les_éléments()
  retour                       ← pas de rendu différentiel ce frame

 Frames suivants : rendu différentiel uniquement 
dessiner_rect(ancienne_x, ancienne_y, NOIR)
dessiner_rect(nouvelle_x, nouvelle_y, COULEUR)

    Le drapeau needsRedraw¶

    Pour les jeux où rien ne bouge automatiquement: Memory, Morpion, Labyrinthe, redessiner à chaque frame est du gaspillage pur : l'écran ne change que quand le joueur appuie sur un bouton.

    Le drapeau needsRedraw est un interrupteur : afficher() ne fait rien si rien n'a changé.

     Initialisation
needsRedraw ← FAUX

 Dans mettreÀJour()
si entrées.bouton_pressé :
  modifier_état_du_jeu()
  needsRedraw ← VRAI        ← signaler qu'un redessin est nécessaire

 Dans afficher()
si NON needsRedraw : retour  ← sortir immédiatement si rien à faire
needsRedraw ← FAUX           ← remettre à zéro avant de dessiner
dessiner_tout()

    Règle : remettre needsRedraw à FAUX au début de afficher(), pas à la fin. Si on le remet à la fin, un événement survenu pendant le dessin serait ignoré.

    Quand utiliser quelle technique ?¶

    Type de jeu Technique recommandée
    Jeu avec objets en mouvement continu (Pong, Snake, Flappy...) Rendu différentiel avec ancienne_position
    Jeu au tour par tour ou sur événement (Morpion, Memory, Labyrinthe) Drapeau needsRedraw + redessin complet conditionnel
    Les deux (Space Invaders : missiles continus + grille statique) Combinaison des deux selon l'élément

    À retenir¶

    • Ne jamais effacer tout l'écran à chaque frame sauf au premier dessin.
    • Toujours sauvegarder ancienne_position avant de calculer la nouvelle.
    • needsRedraw économise des cycles CPU pour les jeux statiques.
    • mettreÀJour() calcule, afficher() dessine — ces deux fonctions ne se mélangent jamais. Voir la section Contrat de Jeu
