    Le contrat de jeux¶

    Le problème à résoudre¶

    La console doit pouvoir gérer 10 jeux complètement différents avec le même code de boucle principale. Comment appeler mettreÀJour() sur un jeu sans savoir si c'est Snake, Tetris ou Pong ?

    Il faut que tous les jeux respectent un contrat commun : un ensemble de fonctions que la console peut appeler sans connaître les détails internes de chaque jeu. Ce pattern s'appelle interface ou classe abstraite selon les langages.

    L'analogie de la prise électrique¶

    La console est le mur électrique. Elle ne sait pas si tu branches un chargeur, une lampe ou un fer à repasser. Mais elle sait que tout appareil compatible aura une fiche standard à deux broches. Le contrat initialiser / mettreÀJour / afficher est cette fiche standard. N'importe quel jeu peut se "brancher" en la respectant.

    Le contrat¶

    Chaque jeu doit obligatoirement implémenter ces fonctions :

    interface Jeu :

  initialiser() :
    // Remettre toutes les variables à leur état de départ
    // Score ← 0, positions initiales, vitesses, grilles vides...
    // Appelé au premier lancement ET à chaque "rejouer"

  mettreÀJour(entrées) :
    // Avancer la logique d'un pas
    // → Lire les entrées, déplacer les entités
    // → Vérifier les collisions
    // → Mettre état ← TERMINÉ si game over
    // ⚠️ Ne jamais dessiner ici

  afficher() :
    // Dessiner l'état actuel sur l'écran
    // ⚠️ Ne jamais modifier la logique ici

  estTerminé() → booléen :
    // Retourner VRAI si la partie est finie

  obtenirScore() → entier :
    // Retourner le score actuel

    La séparation logique / dessin¶

    La règle la plus importante du contrat : mettreÀJour() et afficher() ne se mélangent jamais.

    mettreÀJour() afficher()
    Calcule les nouvelles positions Dessine les positions calculées
    Vérifie les collisions Ne fait aucun calcul
    Lit les entrées N'accède pas aux entrées
    Modifie les variables d'état Lit les variables d'état (lecture seule)
    Ne dessine rien Ne modifie rien

    Pourquoi cette rigueur ?

    • On peut tester la logique sans avoir d'écran (avec des tests unitaires).
    • On peut changer le moteur graphique sans toucher à la physique.
    • Un bug visuel est isolé dans afficher(). Un bug logique est isolé dans mettreÀJour().

    Cycle de vie d'un jeu¶

    lancerJeu(identifiant) :

  // 1. Libérer la mémoire du jeu précédent
  si jeu_actif existe :
    détruire(jeu_actif)
    jeu_actif ← NULL

  // 2. Créer le bon jeu selon l'identifiant
  selon identifiant :
    0 → jeu_actif ← créer(Snake)
    1 → jeu_actif ← créer(Morpion)
    2 → jeu_actif ← créer(Pong)
    3 → jeu_actif ← créer(Breakout)
    ...

  // 3. Initialiser et démarrer
  jeu_actif.initialiser()
  état_console ← PLAYING

    Après le selon, la console n'a aucune idée si jeu_actif est un Snake ou un Tetris. Elle appelle uniquement initialiser(), mettreÀJour(), afficher(), estTerminé() les fonctions du contrat. C'est ça, le polymorphisme.

    Libération mémoire : pourquoi c'est crucial¶

    Chaque jeu est créé dynamiquement en mémoire. Si on crée un nouveau jeu sans supprimer l'ancien, la mémoire de l'ESP32 (320 Ko de RAM) se remplit progressivement jusqu'au crash c'est une fuite mémoire.

    // ✅ Correct : libérer avant de créer
si jeu_actif existe :
  détruire(jeu_actif)     ← rend la mémoire
jeu_actif ← créer(Snake)  ← alloue de la mémoire

// ❌ Fuite mémoire
jeu_actif ← créer(Snake)  ← l'ancien jeu occupe toujours de la mémoire

    Ajouter un nouveau jeu¶

    Grâce au contrat, ajouter un 11e jeu à la console ne nécessite de modifier qu'un seul endroit : le selon dans lancerJeu(). Le reste de la console — boucle principale, menu, game over — ne change pas.

    // Avant
9 → jeu_actif ← créer(Memory)

// Après : ajout de Pac-Man
9 → jeu_actif ← créer(Memory)
10 → jeu_actif ← créer(PacMan)   ← une ligne ajoutée

    PacMan doit simplement respecter le contrat. La console s'en occupe automatiquement.

    À retenir¶

    • Tous les jeux ont la même interface : initialiser, mettreÀJour, afficher, estTerminé, obtenirScore.
    • mettreÀJour ne dessine jamais. afficher ne calcule jamais.
    • Libérer la mémoire de l'ancien jeu avant d'en créer un nouveau.
    • Ajouter un jeu = créer un fichier + ajouter une ligne dans le selon.
